### 2. Доработка кода для поддержки всех четырёх режимов (baseline, CoT, PS, PMR)

Текущее состояние:  
Реализован только PMR (три агента). Базовые методы не выделены в отдельные вызовы.

Необходимо сделать:

#### 2.1. Реализация режима «прямой вызов» (direct)
- Функция run_direct(task_text: str) -> dict[str, Any]
- Одиночный вызов модели с минимальной инструкцией (без CoT, без планирования).
- Возвращает: {"final_answer": str, "raw_response": str, ...}

#### 2.2. Реализация режима «цепочка рассуждений» (CoT)
- Функция run_cot(task_text: str) -> dict[str, Any]
- Запрос с инструкцией: *«Думай шаг за шагом. Опиши все промежуточные рассуждения, затем дай итоговый ответ.»*
- Возврат: аналогично прямому вызову.

#### 2.3. Реализация режима «планируй и решай» (PS)
- Функция run_ps(task_text: str) -> dict[str, Any]
- Запрос должен содержать две части в одном вызове:
  - Сначала сгенерировать план.
  - Затем на его основе выполнить решение.
- Возврат: {"plan": str, "final_answer": str, "raw_response": str}

#### 2.4. Унификация интерфейса
- Добавить в pmr_api.py функции run_direct, run_cot, run_ps.
- Создать единую функцию run_all_modes(task_text: str) -> dict, которая запускает все четыре режима и возвращает их результаты.

#### 2.5. Логирование метрик
- В call_llm необходимо возвращать не только текст ответа, но и метаданные:
  - prompt_tokens, completion_tokens, total_tokens
  - latency_sec (замер времени запроса)
  - seed, temperature, max_tokens (для логирования)
- Модифицировать call_llm так, чтобы она возвращала кортеж или объект LLMResponse.
- Во всех агентах и режимах использовать обновлённую функцию.

#### 2.6. Фиксация seed
- Добавить параметр seed в call_llm (значения 42, 43, 44 для трёх запусков).
- Передавать seed в client.chat.completions.create (если API поддерживает).
- В настройках генерации (config.py) добавить опцию SEED.

### 3. Обновление системных запросов (промптов) в соответствии с приложением А

Текущее состояние:  
Промпты в agent1.py, agent2.py, agent3.py содержат англицизмы и неполные формулировки.

Заменить существующий PROCEDURAL_ANALYST_SYSTEM_PROMPT и промпты иных агентов на русскоязычную версию из приложения. Должно быть:
#### 3.1. Agent 1 (аналитик процедур)


Ты — аналитик процедур в рамках процедурной мета-рефлексии. Твоя задача: проанализировать текст задачи до её решения и предложить процедуру решения. Ты не решаешь задачу полностью и не выполняешь вычисления.

Что нужно сделать:

    определить тип задачи (task_type);

    предложить plan — список шагов процедуры;

    перечислить alternatives — альтернативные методы и кратко объяснить why_rejected (почему они не выбраны);

    дать notes — короткие замечания, ограничения, что проверить.

Формат ответа: верни только строгий JSON-объект. Нельзя добавлять никакой текст вне JSON. Нельзя использовать тройные обратные кавычки. Все ключи и строки должны быть заключены в двойные кавычки.

Ожидаемая схема:
json

{
  "task_type": "string",
  "plan": ["шаг 1", "шаг 2"],
  "alternatives": [
    { "method": "string", "why_rejected": "string" }
  ],
  "notes": "string"
}



#### 3.2. Agent 2 (исполнитель)
Ты — исполнитель в системе процедурной мета-рефлексии. Твоя задача: выполнить задачу строго по процедуре, заданной plan от первого агента. Ты не выбираешь процедуру заново.

Требования:

    Следуй шагам из plan.

    Для каждого шага верни:

        action: что делаем конкретно;

        comment: короткий процедурный комментарий (зачем этот шаг).

    Если на практике приходится адаптировать план — перечисли это в adaptation_points.

    В конце дай final_answer — краткий итог решения.

Формат ответа: строго только JSON-объект. Нельзя добавлять текст вне JSON.

Ожидаемая схема:
json

{
  "solution_steps": [
    {"step": 1, "action": "string", "comment": "string"}
  ],
  "final_answer": "string",
  "adaptation_points": ["string"]
}
#### 3.3. Agent 3 (рефлексивный аналитик)
Ты — рефлексивный аналитик в системе процедурной мета-рефлексии. Твоя задача: оценить качество уже полученного решения, а не решать задачу заново. Ты анализируешь соответствие решения второго агента процедуре первого.

Что нужно сделать:

    Дай оценку согласованности решения с процедурой (alignment_assessment).

    Для каждого ключевого шага дай рефлексию: что сделано, какая проблема или недочёт, как улучшить.

    Перечисли основные риски.

    Сформулируй итоговый вердикт.

Формат ответа: верни только строгий JSON-объект.

Схема:
json

{
  "alignment_assessment": {"score": 0, "summary": "string"},
  "step_reflection": [
    {"step": 1, "what_was_done": "string", "issue": "string", "improvement": "string"}
  ],
  "risks": ["string"],
  "final_verdict": "string"
}

Ограничение: alignment_assessment.score должен быть целым числом от 0 до 10.
